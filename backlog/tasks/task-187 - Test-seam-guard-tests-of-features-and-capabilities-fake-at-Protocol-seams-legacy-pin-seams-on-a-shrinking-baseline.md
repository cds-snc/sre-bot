## Design
New app/bin/check_test_seams.py on freeze_guard.py (iter_python_files, load_baseline, report), two baselines, one Makefile target, one blocking CI step.

Patch calls detected (AST, decorators included): monkeypatch.setattr/delattr, patch / mock.patch / unittest.mock.patch, patch.object, patch.multiple, mocker.patch(.object). Target resolution:
- string targets and (object, "attr") forms; module-level str constants, f-strings and + concatenation of constants are folded (scribe/_SUMMARIZE, comms f"{_MODULE}.x" need it);
- object names resolved through the test file's imports; a test-local class/object is ignored;
- the dotted target is walked through the app tree (static parse, no import): longest module prefix, then each binding's origin (def/class, module-level assignment, import). "Mock where it is looked up" (docs.python.org/3/library/unittest.mock.html#where-to-patch) means the patched name lives in the consumer module, so the guard classifies by where the binding comes from, not where it sits.
Classification of a resolved target:
- edge (allowed): origin outside features/, capabilities/, modules/ (integrations clients, infrastructure settings, stdlib datetime, i18n);
- provider seam (allowed, testing.md): origin is a function in a providers.py or settings.py module inside features/ or capabilities/ (comms get_status_page_publisher, text_generation_available; incident and scribe settings getters);
- internal (violation): any other origin inside the three roots, including module-level variables (logger.warning -> structlog.testing.capture_logs is the replacement);
- unresolved inside a root (violation, fail closed): reported as "<file>::?<line-free expr>" so it can be baselined but never silently passes. An object outside the roots with a dynamic attr (access_sync loop in the registration pin) is an edge.

Zones (path-based, deterministic, mirrors testing-standards layout):
- Strict: tests/{unit,integration}/{features,capabilities}/**. Entry "<tests-relative file>::<dotted target>" per internal patch; set semantics (one entry per file+target). Baseline app/bin/baselines/test_seams_strict.txt, ratchets down.
- Legacy pin: tests/integration/legacy_surface/**. (a) In test_*.py, any internal patch of a features/, capabilities/ or modules/ target is an inline violation (pins patch features internals too: scribe draft/summarize). (b) In conftest.py, an internal patch is allowed only inside a top-level @pytest.fixture whose docstring carries "Owning rebuild task: TASK-<id>"; otherwise a violation. (c) Each allowed conftest seam is an entry "<fixture>::<target>  # TASK-<id>" in app/bin/baselines/test_seams_legacy.txt; inline pin violations go in the same file under their own prefix "inline:<file>::<target>". Trailing "# ..." owner comments are stripped before comparison.
- Everything else (tests/modules, tests/integration/packages, server tests): out of scope; packages/ enters the strict zone when TASK-124 moves it (OQ2).

## Test matrix (test_bin_test_seams_check.py)

Boundary: f-string / constant-folded target resolved; @patch decorator detected; patch.object on an imported features class is internal; dotted walk through an imported integrations module is an edge; duplicates in one file collapse to one entry; trailing owner comments ignored.

Ratchet: removed patch reports a stale entry as INFO and exits 0.
