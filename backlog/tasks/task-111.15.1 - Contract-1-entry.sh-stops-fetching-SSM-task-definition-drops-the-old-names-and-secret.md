## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
First half of TASK-111.15. app/bin/entry.sh no longer fetches sre-bot-config or sre-bot-config-infrastructure, and the task definition drops BACKEND_URL, CORS_ALLOWED_ORIGINS, SLACK__COMMAND_PREFIX and the old GCP_SRE_SERVICE_ACCOUNT_KEY_FILE secret. Dropping CORS_ALLOWED_ORIGINS removes its entry in terraform/templates/sre-bot.json.tpl, the cors_allowed_origins variable (terraform/variables.tf) and its template argument in terraform/ecs.tf. The IAM read on the two blob parameters stays until TASK-111.15.2, so a task from the previous revision (which still fetches them) keeps working through the deploy and any rollback. Under decisions/deployment.md a terraform task-definition change reaches production only at the next deploy: after merge, tf_apply registers the revision, then a workflow_dispatch deploy runs the current image on it and the running revision is checked (runbook: redeploy the current image after a terraform task-definition change).

The declare-path incident values (announcement channel, security and Notify management group ids) move from the legacy IncidentFeatureSettings (infrastructure/configuration/features/incident.py) to [incident_response], owned by IncidentResponseSettings in features/incident/response/settings.py (keys announcement_channel_id, security_group_id, notify_management_group_id; decided 2026-10-28); modules/incident reads them from there, and infrastructure/configuration/features/incident.py is deleted. Values unchanged; the move standardises the keys TASK-111.14 froze ([incident] incident_channel, slack_security_user_group_id, slack_notify_mgmt_user_group_id repeat their table and carry vendor words): lower snake_case keys that do not repeat the table (decisions/configuration.md), fields renamed to match, extra=forbid, base.toml and production.toml renamed in the same PR, HINTS and doc-14 updated for the renamed INCIDENT__* override names (decisions/incident-management.md, Settings).

Sentinel (decided 2026-10-28): the app reads SENTINEL_* only from the blob's .env today, so the reads move here: [sentinel] log_type in the files, SENTINEL__CUSTOMER_ID and SENTINEL__SHARED_KEY as env_only fields, checked before merge by a pre task check sentinel. TASK-171 (row Z2) still rules rebuild-or-delete.
