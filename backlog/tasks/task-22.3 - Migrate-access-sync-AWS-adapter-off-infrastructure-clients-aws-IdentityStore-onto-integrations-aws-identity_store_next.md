- CROSS-ACCOUNT ROLE REQUIREMENT (new finding, not in the 07-31 plan or current AC#1): infrastructure/configuration/integrations/aws.py::AwsSettings.SERVICE_ROLE_MAP maps "identitystore" -> ORG_ROLE_ARN. RATIONALE (confirmed by human, 2026-08-05): the sre-bot's own ECS task runs in an AWS account that is a MEMBER account of the AWS Organization; AWS IAM Identity Center / Identity Store is centrally managed in the Organization's MANAGEMENT account, not in the bot's own account — so identitystore (and, by the same reasoning, sso-admin, also mapped to ORG_ROLE_ARN in SERVICE_ROLE_MAP) genuinely requires assuming a role in the management account for every call. This is why identitystore/sso-admin need role_arn threading while same-account services (e.g. DynamoDB, which lives in the bot's own account and has no SERVICE_ROLE_MAP entry, per TASK-22.2) do not — not an inconsistency, a real architectural difference this migration must preserve. The legacy facade threads this via SessionProvider.build_client_kwargs(service_name="identitystore") on every call. integrations/aws/client.py::get_aws_client(service_name, role_arn=...) supports the identical role assumption (STS AssumeRole then boto3.Session(credentials=...)) via its role_arn param. The new adapter/factory MUST call get_aws_client("identitystore", role_arn=get_aws_settings().SERVICE_ROLE_MAP.get("identitystore") or None) — omitting this would silently run identitystore calls under the bot's own member-account credentials instead of the assumed management-account role, a real production access regression (calls would fail with AccessDenied against the member account's own — nonexistent — Identity Store), not just a style nit.
- PAGINATION: list_users/list_groups/list_group_memberships/list_group_memberships_for_member are today auto-paginated by the old executor (keys=["Users"]/["Groups"]/["GroupMemberships"], force_paginate=True) and `_list_users()`/`_build_group_index()`/`_fetch_current_state()`/`list_group_members()` all expect a flat list back. Confirmed via boto3 client.can_paginate(...) that all 4 have real boto3 paginators registered. Target shape must use `self._identitystore.get_paginator(<op>).paginate(...)` and accumulate the page key, mirroring the ALREADY-SHIPPED precedent in infrastructure/storage/service.py::DynamoDBStorageService.query() (`paginator = self._dynamodb.get_paginator("query"); for page in paginator.paginate(**args): ...`) — same pattern, different vendor.
- TYPED CLIENT: types-boto3[...,identitystore,...] is already a pyproject.toml dev dependency (landed via TASK-70/TASK-22.2). Per decisions/sdk-typing.md item 2, annotate the factory-built handle with this stub type under TYPE_CHECKING (aliased to avoid name collision with the legacy infrastructure.clients.aws.identity_store.IdentityStoreClient, which this migration removes the import of entirely) — do NOT hand-roll a narrower Protocol the way infrastructure/storage/service.py's DynamoDBClient Protocol did; that predates this finding and is an existing minor deviation from sdk-typing.md's literal "annotate with the stub type" wording, out of scope to fix here (not touching storage/service.py).

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Migrated AwsIdentityCenterAdapter off the AWSClients facade onto a typed boto3 identitystore client (types_boto3_identitystore.client.IdentityStoreClient) injected via a new build_aws_identity_center_adapter() factory in adapters/aws_identity_center.py. Root-cause fix: integrations/aws/client.py::get_aws_client() previously called sts.assume_role() eagerly when role_arn was set, which broke app-startup tests once the identitystore adapter began invoking it during the packages.access.sync startup_warmup pluggy hook; changed to use botocore DeferredRefreshableCredentials/create_assume_role_refresher so AssumeRole is deferred to the first real API call (matches prior lazy facade behavior; no other current get_aws_client caller passes role_arn, so this is a safe, behavior-neutral change). Test suite: fixed a MagicMock config bug in 4 test_aws_identity_center_adapter.py tests where describe_group.return_value was set without clearing the fixture's default describe_group.side_effect (side_effect silently wins over return_value), added client.describe_group.side_effect = None before each override. Test evidence: tests/unit/packages/access/sync + tests/integration/packages/access/sync + tests/integration/integrations/aws/test_identity_store_conformance.py = 182 passed. Full suite (tests --ignore=tests/smoke --ignore=tests/unit/modules/aws, the latter a pre-existing unrelated collection break) = 2959 passed, 5 pre-existing unrelated failures (test_client_next.py x2, test_webhooks_aws_sns.py x3) verified identical on unmodified baseline. ruff check . clean; mypy clean on all 3 touched files (integrations/aws/client.py, packages/access/sync/adapters/aws_identity_center.py, packages/access/sync/providers.py).
