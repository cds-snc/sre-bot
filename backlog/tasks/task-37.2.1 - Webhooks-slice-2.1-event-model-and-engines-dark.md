Scope:
- Generate app/capabilities/webhooks/ with the package generator (TASK-114.2); declare its pyproject entry point and enablement key.
- Domain, as frozen dataclasses: InboundEvent with the CloudEvents attribute names (id = the protocol delivery id or a server-generated local:<uuid>; source = the instance_ref, never the URL token; type = set by the matched sender kind, never read from the payload; time; optional subject; data = only the kind's validated, extracted fields). Event types alert (title, summary, status firing | resolved | info, severity, dedup_key, links; dedup_key and status carried but unused in v1), notification and slack.passthrough. SenderKind. WebhookInstance with instance_ref, owner, auth_tier, protocol, an ordered list of sender kinds and destinations.
- The sender-kind file model (pydantic at the file boundary) registered as the first content kind, webhooks/sender-kinds, through register_content_kinds, with its JSON Schema exported. No files land yet (TASK-37.3), so the kind is not required in this slice and boot is unchanged.
- Engines: a declarative condition matcher (the first matching kind in the instance's declared order wins); python-jsonpath extraction with singular paths only; a python-liquid 3.x renderer (plain text, StrictUndefined, every limit set, no file loader, names checked at boot). No regex in content (security.md linear-processing rule).
- A Slack channel-poster adapter on AsyncWebClient that escapes every content-derived value (&, <, >) before inserting trusted tokens; links only from validated https fields.
- The webhooks event-consumer hookspec (consumers by event type, handlers by id), collected once at startup.
- The linear, token-bounded email matcher with a Slack lookup cap (TASK-190 hand-off F-I: today one users_lookupByEmail per match, unbounded).
- The [webhooks] settings slice with defaults for the limits this slice uses.

Out of scope: protocols, the inbox, ingest and any route (TASK-37.2.2); the sender-kind files, the Notify handler and the incident alert consumer (TASK-37.3); instance attributes in storage (TASK-37.4.1).

Size: ~400 production LOC, ~9 files (under the gate; OQ10 split of the old 37.2).
Production: dark. No route, no instance, no traffic.

## OWASP and industry review (2026-11-26, human: "adjust for industry best practices, OWASP knowledge base; course-correct a prior ADR carefully")
Corrections to decisions/webhooks.md, each in this PR with a Changes line. They are expand-only: no code depends on the old text.
1. Link URLs: escaping &, < and > is not enough, because a URL holding "|", ">" or a space breaks out of Slack's <url|label> syntax (Slack: "URLs with spaces will break"). An https field is parsed with urllib.parse. It is refused if it has userinfo, no host, a non-https scheme, control characters, or is over [webhooks] max_url_chars (default 2048). The host is IDNA-encoded to punycode, and the URL is rebuilt from its parsed parts with the delimiters, spaces and controls percent-encoded. A kind may declare allowed_hosts per URL field. (OWASP Unvalidated Redirects and Forwards: a maintained parser, reject userinfo and ambiguous input, use the validated URL itself; OWASP XSS Prevention: URL-encode components.)
2. Link labels are fixed wording: a label template may name instance.name and received_at, never fields.*, because a payload label over a payload URL is a phishing primitive (OWASP Unvalidated Redirects).
3. Unicode in extracted text: NFC-normalised; C0 and C1 controls other than \n and \t, bidi embeddings, overrides and isolates (U+202A-202E, U+2066-2069, U+200E, U+200F, U+061C) and Default_Ignorable code points (zero-width) are removed before any template or the adapter sees them. No NFKC, no homoglyph rewriting. (Trojan Source, CVE-2021-42574; UTS #39; OWASP Input Validation: normalisation is not sanitisation and does not replace output encoding, which the adapter still applies.)
4. List values: at most [webhooks] max_list_items elements (default 50), as well as the per-value character cap (OWASP API4:2023, array sizes).
5. Liquid filters: an allowlist of string, number, list and date filters. strip_html (regex), base64_decode, url_decode, escape, escape_once, h, safe, escapejs and newline_to_br are removed. The webhooks.md "local namespace" limit does not exist in python-liquid 3, and the assign and capture tags are removed, so the question is moot. Templates parse at boot only, never per request, so the parse-time hang in python-liquid < 2.2.1 (CVE-2026-55865) is excluded by the >= 3.0.0 floor.
6. Email finder: OWASP no longer states the 254/64 limits, which are RFC 5321's, so the citation is RFC 5321. It tokenises with str.split, uses no regex, lowercases the domain, and caps the number of candidates.
Moved to later slices (task comments and ACs added):
- TASK-37.2.3: mrkdwn objects that carry payload text set verbatim: true; plain_text is used wherever no trusted token is needed; truncation happens after escaping; every Slack call has a timeout and a bounded retry (OWASP API10).
- TASK-37.2.2: strict JSON decoding (RFC 7493 I-JSON): duplicate member names, NaN and Infinity, lone surrogates and non-finite numbers are rejected, a depth limit is set, and a RecursionError is caught, each answering a stable 400 (Bishop Fox JSON interoperability; stdlib json silently keeps the last duplicate key).
New settings for this slice: max_url_chars 2048 and max_list_items 50. New tests: test_webhooks_field_extraction_urls.py and test_webhooks_field_extraction_unicode.py. AC #4 covers the URL and Unicode rules through extraction.
